# CCD vs Multi-rate — демонстрация 2D-физики

Упрощённая демонстрация 2D-физики твёрдых тел (круги + статические AABB), которая сравнивает:

1. **Дискретное обнаружение столкновений** на 60 Гц — быстрый снаряд туннелирует сквозь тонкую стенку.
2. **CCD** — метод заметания круга по AABB (slab method), находит точное время контакта внутри шага.
3. **Multi-rate** — обычные объекты на 60 Гц, быстрые снаряды на 240 Гц (4 подшага за кадр).
4. **Всё на 240 Гц** — для сравнения: тот же бюджет подшагов, но применён ко всем объектам.

## Требования

- Python 3.8+
- `pygame>=2.0`

```bash

```

## Управление

| Клавиша | Действие |
|---------|----------|
| `1` | DISCRETE (60 Гц, наивная проверка пересечения) |
| `2` | CCD (60 Гц, метод заметания круга по AABB) |
| `3` | MULTIRATE (медленные @ 60 Гц, быстрые @ 240 Гц) |
| `4` | ALL_240 (всё @ 240 Гц) |
| `R` | сбросить сцену |
| `ESC` | выход |

## Что вы должны увидеть

- **Режим 1 (DISCRETE):** красный снаряд пролетает сквозь серую стенку толщиной 10 px.
- **Режим 2 (CCD):** снаряд отскакивает от стенки — метод заметания находит время контакта.
- **Режим 3 (MULTIRATE):** снаряд отскакивает — 240 Гц дают в 4 раза меньшие подшаги.
- **Режим 4 (ALL_240):** тот же результат, что и в 3, но физика на кадр дороже, так как медленные объекты тоже обновляются на 240 Гц.

HUD (интерфейс на экране) выводит время физики (ms/frame) и количество подшагов за кадр.

## Примечания по реализации

### CCD

Для метода заметания круга по статическому AABB нужно расширить AABB на радиус круга
(`min_x = bx - hx - r` и т.д.) и пересечь луч
`p(t) = p0 + v * t` с каждой осью (слэбом). Значение `t_near` для двух
слэбов — это время первого контакта (как доля от шага). Нормаль берётся
из того слэба, который дал `t_near`.

`step_ccd` делает не более 8 итераций на тело: находит самое раннее столкновение → перемещает
туда → отражает → продолжает с оставшимся временем. Крошечный сдвиг позиции
предотвращает повторное обнаружение того же контакта при `t=0`.

### Multi-rate

`step_multirate` делает `ratio` подшагов по `dt_frame/ratio` для быстрых тел,
затем один полный шаг для медленных. Реакция на столкновение внутри каждого подшага — это
обычное дискретное пересечение + выталкивание + отражение.

### Детерминированность

`random.seed(42)` в `Scene._make_dynamics` → идентичная сцена при каждом сбросе.
Шаги физики детерминированы (нет `random` в цикле).

## Известные ограничения

- Столкновения динамических тел между собой **не** реализованы; только динамических со статическими.
  Это сделано, чтобы сфокусировать демо на CCD / multi-rate.
- Multi-rate уменьшает туннелирование, но не устраняет его: на 240 Гц достаточно быстрый
  снаряд всё ещё может проскочить достаточно тонкую стенку.
- CCD обрабатывает не более 8 контактов на тело за шаг.
- Дискретный решатель пересечений предполагает, что тело подошло с определённой
  стороны; если тело протуннелирует в *середину* толстой стены, выталкивание может выбрать
  неверную сторону.
